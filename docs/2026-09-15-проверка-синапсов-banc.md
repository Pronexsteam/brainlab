# Проверка: недобор синапсов BANC — в нативной таблице или только в edgelist Lee-lab?

Вопрос из `docs/2026-09-15-анализ-banc-сахар-mn9.md` (§4, §7) и `2026-09-15-записка-banc.md` («чем опровергается»):
у клеток пути сахар → MN9 в BANC v888 по `banc_888_edgelist_simple_v3.feather` входов ≈0,39 от FAFB v783 (MN9 2816 против 8021,
DNge062 679 / 2560, DNge080 879 / 4254). Это видно и в нативной таблице синапсов, или так скомпилирован edgelist (порог по score)?

Скрипт: `lab/analysis/banc_native_synapses.py` (один проход по `banc_888_synapses_v3_enriched.parquet`, 198 816 365 строк, 1989 row group,
4 столбца, ≈4 мин; по `fafb_783_synapses.parquet`, 55 595 125 строк, ≈2,5 мин; кэш гистограмм во временной папке, `--stage report` — только отчёт).
Все числа ниже — из его вывода. Клетки пути берутся из `data/store.sqlite` (BANC: cell_type или extra.fafb_cell_type точно равен типу, без `auto:`).

## Коротко

1. **Edgelist BANC = нативная таблица без единого порога**, только с ограничением «pre и post — среди 188 508 клеток meta». Нативных строк
   198 816 365; с post ∈ meta 57 003 879 (28,7 %); с pre и post ∈ meta **42 309 621 = Σcount edgelist 42 309 621** ровно. По клеткам:
   вход 100 % клеток (167 018) совпадает точно; по парам pre→post для MN9 и DNge062 — 812 из 812 пар совпадают синапс в синапс.
   Никакого фильтра по mean_score, size или числу синапсов в паре (7,37 млн пар с count = 1) в edgelist нет.
2. **Недобор есть в нативных данных.** С тем же ограничением (pre ∈ meta) BANC/FAFB по типам 0,21–0,61, медиана **0,35**; если в BANC
   взять все входы, включая от сегментов вне meta (невычитанные фрагменты, 22–29 % входа клеток пути), — 0,28–0,83, медиана **0,47**.
   Даже в самом щедром счёте у MN9 3822 входа против 7753, у DNge080 1155 против 4149.
3. **Порог по score не при чём и на согласованном фильтре**: если в каждом наборе оставить верхние 75 / 50 / 25 % синапсов по своему score,
   отношение не меняется (MN9 0,36 → 0,36 → 0,33 → 0,32; DNge080 0,21 → 0,21 → 0,20 → 0,20). Недобор — во всём распределении score, не в хвосте.
4. Оговорка: сама нативная таблица v3 уже обрезана до нас — mean_score ≥ ~0,05 (мягкий край: 20 строк в корзине 0,051, 320 470 в 0,062,
   5-й процентиль 0,072, медиана 0,118) и size ≥ 10 (медиана 41). Что было отброшено ниже 0,05 — по этому файлу не видно; шкала score
   не сопоставима с FlyWire cleft ≥ 50. У FAFB parquet — тоже уже фильтрованный (confidence min 51, жёсткий край: 158 106 строк в 51).
5. **Вывод для записки:** причина остаётся на стороне данных BANC (детекция синапсов с их порогом и/или неполная вычитка пресинаптических
   фрагментов), а не в компиляции edgelist Lee-lab. Записку слать команде BANC; «опровержение через нативную таблицу» закрыто.

## 5. Вердикт

- **Недобор 0,35–0,47 присутствует в нативной таблице BANC v3.** Edgelist Lee-lab не вводит порога: это нативная таблица, сведённая к парам
  клеток из meta (42 309 621 синапс ровно, 100 % клеток и пар совпадают). Гипотеза «компиляция edgelist» закрывается.
- Что даёт часть разрыва — **невычитанные пресинаптические фрагменты**: 22–29 % входа клеток пути в BANC идёт от сегментов, которых нет среди
  188 508 клеток meta (по мозгу: медиана входа central_brain 212 против 145). Их отбрасывают и edgelist, и наш граф; но и с ними BANC/FAFB
  0,47 (MN9 0,49, DNge080 0,28). Это признак неполной вычитки/сборки (orphan-аксоны), а не порога.
- Остаток (≈ ×2 при всех pre) — **детекция синапсов** в BANC, включая порог, применённый самой командой BANC до выкладки таблицы v3
  (mean_score ≥ ~0,05, size ≥ 10): нам ниже него не видно, а шкала score не сравнима с FlyWire cleft ≥ 50. Внутри доступного диапазона
  отношение стабильно (0,32–0,36 у MN9 на любом квантиле), так что «жёсткий детектор» объяснил бы разрыв только если бы пропущенные синапсы
  лежали ниже 0,05 целиком, — проверить нельзя без сырой таблицы BANC.
- Вероятности из анализа (0,70 детекция / 0,15 разметка / 0,10 наш артефакт / 0,05 биология) → **0,75 данные BANC** (из них ≈ 0,5 детекция
  с их порогом, ≈ 0,25 неполная вычитка пресинаптических фрагментов) / **0,12 разметка** (DNge059 справа, auto:DNge062, CB0824 — без изменений)
  / **0,08 наше** (компиляция edgelist исключена; остаётся перенос абсолютного веса Shiu между сканами) / **0,05 биология**.
- **Записка:** адресат — команда BANC (и, для сведения, Lee-lab как владелец bucket), не «вопрос к Lee-lab о фильтре». Пункт «чем опровергается —
  подтверждение, что низкие числа — намеренный фильтр edgelist_simple_v3» из обеих записок убрать: проверено, фильтра нет. Добавить: (а) числа
  сверены с нативной `synapses_v3`: edgelist = нативная таблица ∩ meta; (б) 22–29 % входа клеток пути — от сегментов вне meta; (в) вопросы к BANC:
  какой порог применён к таблице v3 (mean_score / size) и сопоставим ли он с FlyWire cleft ≥ 50; полна ли вычитка пресинаптических аксонов в
  GNG/премоторной области v888; есть ли оценка recall детектора синапсов в этой области. Ручная сверка в BANC Codex (записка, «что с этим делать»)
  больше не нужна как условие отправки — она заменена этой проверкой.
